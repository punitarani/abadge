`@abadge/sdk` is the official TypeScript client for the abadge API. It wraps the `/v1` REST API and exposes two clients: `AbadgeUserClient` for operator-scoped management and `AbadgeAgentClient` for agent-scoped secret access.

## Install

<CodeGroup>
```bash bun
bun add @abadge/sdk
```

```bash npm
npm install @abadge/sdk
```

```bash pnpm
pnpm add @abadge/sdk
```

```bash yarn
yarn add @abadge/sdk
```
</CodeGroup>

## Quick reference

| Client | Auth | Use for |
|---|---|---|
| `AbadgeUserClient` | Operator session token or personal API key (`abu_`) | Manage organizations, profiles, items, agents, permissions, audit |
| `AbadgeAgentClient` | Ed25519 keypair session (`abs_`) | Read secrets via `access.*` |

```ts
import { AbadgeUserClient, AbadgeAgentClient } from "@abadge/sdk";
```

## Type exports

The SDK re-exports every domain type from `@abadge/core`:

```ts
import type {
  ItemKind,
  StorageMode,
  AgentKind,
  AgentLocality,
  Capability,
  AuditEventType,
  AuditResult,
  ItemPayload,
} from "@abadge/sdk";
```

Helpers:

```ts
import { resolveFieldValue } from "@abadge/sdk";
import { AbadgeApiError } from "@abadge/sdk";
```

## What the SDK does for you

- Builds each `/v1` request with the correct shape
- Adds the right `Authorization` header
- Surfaces typed responses (no `any`)
- Wraps every API error in `AbadgeApiError` (with `code`, `message`, `hint`, `meta`)
- For `AbadgeAgentClient`: handles the keypair challenge / session exchange and refreshes the session at T-2 minutes before expiry

## What the SDK does not do

- Not a daemon. The SDK is a pure HTTP client. Local zero-knowledge decryption is the daemon's job.
- Not a CLI. For human operator workflows, use the dashboard or the `abadge` CLI.
