---
title: "permissions.*"
description: "Capability-based grants linking agents to items."
---

The `permissions` router creates and revokes the `(agent, item, capability)` grants that authorize access. The capability matrix is enforced both at create time and at every access.

## `permissions.create`

**Tier:** `sessionProcedure`

Grants one or more capabilities to an agent on an item in a single atomic batch. Either every capability lands or none does.

<ParamField path="agentId" type="string" required>
  Agent receiving access.
</ParamField>
<ParamField path="itemId" type="string" required>
  Target item. Must belong to the same organization as the agent.
</ParamField>
<ParamField path="capabilities" type="string[]" required>
  Non-empty array of distinct capabilities. Each must be one of `read_ciphertext`, `reveal_plaintext`, `mount_env`, or `mount_file`. Duplicates within the array are rejected by the schema.
</ParamField>
<ParamField path="expiresAt" type="string">
  ISO 8601 timestamp applied to every capability in this submission.
</ParamField>

**Returns:** `{ permissions }` — one row per capability granted.

Creation-time validation rejects the entire batch when:

| Combination | Error | `meta` |
|---|---|---|
| Any capability invalid for the agent's locality | `INVALID_CAPABILITY_LOCALITY` | `invalidCapabilities: string[]` |
| Any capability invalid for the item's storage mode | `INVALID_CAPABILITY_STORAGE` | `invalidCapabilities: string[]` |
| Any `(agent, item, capability)` already exists | `PERMISSION_ALREADY_EXISTS` | `duplicateCapabilities: string[]` |

The composite unique constraint `(agentId, itemId, capability)` keeps each triple at most one row. The router pre-checks for duplicates with a single `IN` query so the error surfaces every offending capability, not just the first.

## `permissions.list`

**Tier:** `sessionProcedure`

<ParamField path="agentId" type="string">
  Filter to grants for one agent.
</ParamField>
<ParamField path="itemId" type="string">
  Filter to grants on one item.
</ParamField>

When both filters are provided, they are AND-combined — useful for asking "what capabilities does this agent already have on this item?"

**Returns:** `{ permissions }` — one row per capability.

## `permissions.revoke`

**Tier:** `sessionProcedure`

<ParamField path="permissionId" type="string" required />

**Returns:** `{ ok: true }`.

In-flight access attempts that have not yet checked the row see the deletion and are denied.

## Audit events

- `permission.create`
- `permission.revoke`
- `permission.revoke_cascade` — emitted when an item or agent is deleted with permissions still attached
