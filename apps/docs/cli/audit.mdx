---
title: "abadge audit"
description: "Inspect the immutable audit log from the CLI."
---

`abadge audit` lists the recent audit log for the active organization. Use `--json` to pipe into `jq` for structured queries and further filtering.

## Usage

```bash
abadge audit
abadge audit --limit 100
abadge audit --json | jq '.entries[] | select(.result == "denied")'
```

## Flags

| Flag | Description |
|---|---|
| `--limit <count>` | Number of entries to fetch (1–100; API default is 50) |
| `--cursor <cursor>` | Pagination cursor returned from a previous response |
| `--json` | Print machine-readable JSON (the raw API response) |

The CLI exposes only pagination flags. All filtering — by event type, agent, item, result, surface, or field — is done either with `jq` on `--json` output or via the `GET /v1/audit` endpoint directly.

## Default output

```
ID     Agent        Item        Event                  Outcome   Mode   Time
123    ci-deploy    prod-db     access.reveal          allowed   -      2026-04-18T01:14:22Z
122    ci-deploy    -           agent.session_issue    allowed   -      2026-04-18T01:13:55Z
121    -            prod-db     permission.create      allowed   -      2026-04-18T01:10:10Z
```

## Pagination

If there are more entries, the CLI prints `Next cursor: <value>` after the table. Pass it to the next invocation:

```bash
abadge audit --cursor <value>
```

## Scripting

For structured filtering, pipe JSON into `jq`:

```bash
# Every denied access in the last 100 events
abadge audit --limit 100 --json | jq '.entries[] | select(.result == "denied")'

# Everything one agent did
abadge audit --limit 100 --json | jq '.entries[] | select(.agentId == "agent_...")'

# Walk every entry with a cursor
NEXT=""
while true; do
  RESP=$(abadge audit --json --cursor "$NEXT")
  echo "$RESP" | jq -r '.entries[]'
  NEXT=$(echo "$RESP" | jq -r '.nextCursor // empty')
  [ -z "$NEXT" ] && break
done
```

For first-class filters (by event type, agent, item, result, surface, or field), call the API directly: the [`GET /v1/audit`](/api/overview) endpoint accepts all of them.

## What audit captures

See [Audit log](/concepts/audit-log) for the full event catalog. Categories include `auth.*`, `agent.*`, `permission.*`, `item.*`, `profile.*`, and `access.*`.

## What audit does not capture

- Secret values
- Encryption material
- Subprocess output from `abadge run`
