## `abadge permission create`

Grant one or more capabilities for an agent on an item. Multiple
capabilities land atomically — either every row is written or none is.

`permission create` always targets a single item, so it accepts only the
legacy capability names: `read_ciphertext` and `reveal_plaintext` (mapped
to canonical `read`), and `mount_env` and `mount_file` (mapped to canonical
`use`).

```bash
# Allow an agent to inject a server-managed secret as an env var
abadge permission create \
  --agent-id <agent-id> \
  --item-id <item-id> \
  --capability mount_env

# Grant several capabilities atomically — repeat the flag or comma-separate
abadge permission create \
  --agent-id <agent-id> \
  --item-id <item-id> \
  --capability mount_env \
  --capability mount_file

abadge permission create \
  --agent-id <agent-id> \
  --item-id <item-id> \
  --capability mount_env,mount_file

# With expiry — applied to every capability in this batch
abadge permission create \
  --agent-id <agent-id> \
  --item-id <item-id> \
  --capability reveal_plaintext \
  --expires-at 2026-12-31T00:00:00Z
```

| Flag | Required | Description |
|---|---|---|
| `--agent-id <id>` | yes | Target agent |
| `--item-id <id>` | yes | Target item |
| `--capability <cap>` | yes | One of `read_ciphertext`, `reveal_plaintext`, `mount_env`, `mount_file`. Repeat the flag or comma-separate to grant multiple. |
| `--expires-at <ts>` | no | ISO timestamp expiry; applied to every capability in this submission |
| `--json` | no | Print raw JSON |

<Note>
  The canonical capabilities `read` / `use` apply to **profile-target**
  grants. Item-target grants — the only kind the CLI creates — reject
  canonical names, so use the legacy aliases above.
</Note>

### Capability legality

Capability legality depends on the agent's locality and the item's storage
mode (ZK = zero-knowledge, SM = server-managed):

| Legacy capability | Canonical | Local + ZK | Local + SM | Remote + ZK | Remote + SM |
|---|---|---|---|---|---|
| `read_ciphertext` | `read` | ✓ | ✗ | ✗ | ✗ |
| `reveal_plaintext` | `read` | ✗ | ✓ | ✗ | ✓ |
| `mount_env` / `mount_file` | `use` | ✓ | ✓ | ✗ (no daemon) | ✗ (no daemon) |

<Warning>
  Profile-target grants are not available from the CLI. Use the
  dashboard's profile-grant flow — it surfaces the blast-radius
  confirmation before granting canonical `read` on a whole profile.
</Warning>

## `abadge permission list`

```bash
abadge permission list
abadge permission list --agent-id <agent-id>
abadge permission list --item-id <item-id>
abadge permission list --json
```

| Flag | Description |
|---|---|
| `--agent-id <id>` | Filter to one agent |
| `--item-id <id>` | Filter to one item |
| `--json` | Print raw JSON |

Output columns: `ID`, `Agent`, `Target`, `Capability`, `Expires`,
`Created`. `Target` shows either the item ID or `profile:<id>` for
profile-target grants.

## `abadge permission revoke <permission-id>`

Revoke a permission immediately. In-flight access attempts that haven't
yet checked the row see the deletion and are denied.

```bash
abadge permission revoke <permission-id>
```
