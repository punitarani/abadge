The dashboard is the operator surface for abadge. It runs at [abadge.io](https://abadge.io) (or your self-hosted deployment) and is built with Next.js App Router.

## Layout

The dashboard is organized around the active organization:

| Section | What you do there |
|---|---|
| Overview | Recent activity, item counts, agent counts |
| Profiles | Create profiles, bootstrap zero-knowledge encryption, manage recovery keys |
| Items | Browse, create, update, and delete credentials |
| Agents | Register agents, view bootstrap tokens, revoke |
| Permissions | Grant capabilities, set expiries, revoke |
| Audit | Inspect every event, filter by agent / item / type |
| Settings | Organization settings, members, API keys, vault security |

The active organization is shown in the header. Switch organizations from the org switcher; every subsequent action targets the new active org.

The Overview leads with a posture banner that reflects the active workspace. A **team organization** runs in **custody mode**: you manage permissions and audit access on behalf of your users and the dashboard never reveals plaintext. A **personal account** is framed as your own vault — you own every secret and can reveal your own values from an item's page. See [Items](/dashboard/items#custody-mode-vs-personal-vault).

## When to use the dashboard vs the CLI

| Task | Best surface |
|---|---|
| Initial onboarding (sign up, first profile, first item) | Dashboard |
| Bulk import from `.env` | CLI (`abadge import`) |
| Day-to-day item edits | Dashboard or CLI |
| Granting and revoking permissions | Either |
| Long-running secret injection | CLI (`abadge run`) |
| Auditing access | Dashboard for filters; CLI for `--json` piping |

The dashboard does not run the CLI's local daemon. Zero-knowledge decryption in the dashboard happens in browser memory (Tier 2 trust). For high-security operations, prefer the CLI plus daemon.

## Browser trust model

When you unlock a zero-knowledge profile in the dashboard, the browser derives the KEK from your master password (Argon2id) and unwraps the root key into JavaScript memory. The key is lost when the tab closes.

<Warning>
  The browser is more exposed than the CLI: a successful XSS attack can steal the unlocked root key. Use the dashboard for management, but reach for the CLI when you need maximum confidentiality.
</Warning>
