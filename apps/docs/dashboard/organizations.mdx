Every resource in abadge belongs to an organization. The dashboard always operates against the **active organization**, shown in the header.

## Creating an organization

<Steps>
  <Step title="Open the org switcher">
    Click the organization name in the header.
  </Step>
  <Step title="Choose Create organization">
    Enter a display name. The slug is auto-generated; override it if you want a specific URL fragment.
  </Step>
  <Step title="Land inside the new org">
    The dashboard switches context. The new org has no profiles, items, agents, or permissions yet.
  </Step>
</Steps>

## Switching organizations

The org switcher lists every organization you're a member of. Selecting one updates the active context and reloads the items, agents, permissions, and audit views.

The active organization is also persisted to the Better Auth session, so subsequent dashboard visits land in the same place.

## Inviting members

<Steps>
  <Step title="Open Settings → Members">
    Available to `owner` and `admin` roles.
  </Step>
  <Step title="Click Invite">
    Choose a role: `owner`, `admin`, or `member`. The dashboard generates a one-time invite token.
  </Step>
  <Step title="Send the invite link">
    Copy the link from the success dialog and send it through your usual channel. The link expires after 7 days; the token can be redeemed exactly once.
  </Step>
  <Step title="Recipient accepts">
    The recipient signs in (or creates an account) and lands at `/invite/accept?token=...`. After confirming the org name and role, they're added with the assigned role.
  </Step>
</Steps>

<Warning>
  The invite token is shown once. Only its SHA-256 hash is stored. If you lose the link, revoke the pending invitation and create a new one.
</Warning>

## Member roles

| Role | Can do |
|---|---|
| `owner` | Everything, including delete the organization |
| `admin` | Invite, remove, and update members; manage org settings |
| `member` | Read org resources; create and manage their own agents and items |

## Managing members

The members table on **Settings → Members** lets owners and admins:

- Change a member's role
- Remove a member (cascades agent revocation)
- Revoke a pending invitation

## Personal API keys

**Settings → API keys** lets you mint personal API keys to script the management surface without a browser. Each key is bound to your user and the active org.

<Steps>
  <Step title="Click New API key">
    Give it a name and an optional expiry.
  </Step>
  <Step title="Copy the secret">
    The success dialog shows the full `abu_...` secret exactly once. The server stores only its SHA-256 hash plus an 8-character prefix.
  </Step>
  <Step title="Use it as a bearer token">
    Send `Authorization: Bearer abu_...`, or pass it as the `sessionToken` to `AbadgeUserClient`.
  </Step>
</Steps>

The keys table lists each key's name, prefix, expiry, last-used time, and enabled/revoked state. **Revoke** disables a key immediately.

<Warning>
  A personal API key authenticates the **management surface only** — organizations, profiles, items metadata, agents, permissions, audit, settings. It resolves to a session identity, **not** an agent, so it can never reveal or mount secret values. Reading secrets still requires a keypair agent plus an explicit permission. A personal API key also cannot create or revoke other API keys — use a browser session for that.
</Warning>

See [Authentication](/api/authentication) for personal API key details.

## Removing the organization

**Settings → Danger zone** deletes the organization (or personal account). Deletion cascades to its agents, permissions, profiles, and items. Audit entries persist (they have no foreign-key constraints). This is irreversible.

Deletion is **not** blocked when items exist — those items are deleted along with everything else. Because the action is destructive, the confirmation dialog requires three things, two of which are re-checked server-side:

<Steps>
  <Step title="Type `delete`">
    A friction step so the action can't be triggered by a stray click.
  </Step>
  <Step title="Type the exact organization name">
    Must match the org's current name (GitHub-style). Re-verified by the server — a mismatch returns `CONFIRMATION_MISMATCH`.
  </Step>
  <Step title="Re-enter your account password">
    Owning the org is not enough; the server re-authenticates the password against your credential account. A wrong password returns `REAUTH_FAILED`; a social-login-only account with no password set returns `REAUTH_PASSWORD_REQUIRED` (set a password via password reset first).
  </Step>
</Steps>

Only an **owner** can delete the organization. Both allowed and denied attempts are written to the audit log.
