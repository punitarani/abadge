title: "Claude Desktop"
description: "Drop-in mcpServers JSON snippet for Claude Desktop and other MCP clients."
---

The MCP server runs as a subprocess that the host client launches over stdio. Most clients accept
a JSON config that lists MCP servers and their startup commands.

## Quick setup with the abadge CLI

The fastest path: register a local MCP agent and let the CLI emit the config snippet for you.

```bash
# Install both binaries (CLI + MCP server)
curl -fsSL https://raw.githubusercontent.com/punitarani/abadge/main/install.sh | bash

# Authenticate
abadge login

# Register an MCP agent and print the Claude Desktop config block
abadge agent add --kind local_mcp --name claude-desktop --mcp-config
```

The last command prints something like:

```json
{
  "mcpServers": {
    "abadge": {
      "command": "/Users/you/.abadge/bin/abadge-mcp",
      "env": {
        "ABADGE_API_URL": "https://api.abadge.io",
        "ABADGE_AGENT_ID": "agent_01HZ...",
        "ABADGE_PRIVATE_KEY_PATH": "/Users/you/.abadge/agents/agent_01HZ....ed25519.jwk"
      }
    }
  }
}
```

Paste the inner `mcpServers.abadge` object into Claude Desktop's config (macOS:
`~/Library/Application Support/Claude/claude_desktop_config.json`), restart Claude, and the
abadge tools should appear.

<Tip>
  Use the **absolute path** for `command`. Claude Desktop is launched by `launchd`/`systemd`
  with a minimal `$PATH` that does not include `~/.abadge/bin`, so a bare `abadge-mcp` will fail
  with "spawn ENOENT" or similar. The `--mcp-config` flag always emits absolute paths.
</Tip>

If you already registered the agent and just need the snippet again:

```bash
abadge agent mcp-config <agent-id>
```

## Manual setup

If you'd rather hand-write the config, the shape is:

```json
{
  "mcpServers": {
    "abadge": {
      "command": "/Users/you/.abadge/bin/abadge-mcp",
      "env": {
        "ABADGE_API_URL": "https://api.abadge.io",
        "ABADGE_AGENT_ID": "agent_...",
        "ABADGE_PRIVATE_KEY_PATH": "/Users/you/.abadge/agents/agent_....ed25519.jwk"
      }
    }
  }
}
```

Replace:

- `command` with the absolute path to your installed `abadge-mcp` (default `~/.abadge/bin/abadge-mcp`)
- `ABADGE_API_URL` with your deployment
- `ABADGE_AGENT_ID` and `ABADGE_PRIVATE_KEY_PATH` with the values from `abadge agent add
  --kind local_mcp` (or whatever you've stored in `~/.abadge/config.json` under
  `localAgents.mcp`)

Restart Claude Desktop after editing.

## Other MCP clients

Any MCP-compatible client that supports stdio transport works the same way. Provide:

- A way to launch the subprocess (`/Users/you/.abadge/bin/abadge-mcp`, or
  `bun packages/mcp/src/index.ts` from the monorepo for development)
- Environment variables to point it at the API and the agent's private key

## Verifying the connection

Once configured, the host client should list the abadge tools (`list_items`, `use_secret`,
`mount_secret`, `release_mount`, `get_audit`) under the `abadge` server.

If the tools don't appear:

1. Check the host client's MCP server log (Claude Desktop logs to `~/Library/Logs/Claude/` on macOS).
2. Run the server manually from a terminal to see startup errors:
   ```bash
   ABADGE_API_URL=... ABADGE_AGENT_ID=... ABADGE_PRIVATE_KEY_PATH=... abadge-mcp
   ```
3. Confirm the agent is enabled with `abadge agent list`.

## Permissions

The MCP server can only access items where the configured agent has an explicit permission. Grant
the right capability before invoking a tool:

```bash
abadge permission create \
  --agent <mcp-agent-id> \
  --item <item-id> \
  --capability mount_env
```

`mount_env` and `mount_file` are the typical capabilities for MCP — `use_secret` calls
`access.mount` with `mountType: env`, and `mount_secret` calls it with `mountType: file`.
