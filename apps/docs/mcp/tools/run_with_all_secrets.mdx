---
title: "run_with_all_secrets"
description: "Run a command with every env-var-shaped item in the named profile injected as a separate environment variable. Profile is the trust boundary — items in other profiles are never injected."
---

`run_with_all_secrets` is the bulk equivalent of [`run_with_secret`](/mcp/tools/run_with_secret). It calls `access.bulkMountEnv` for the named profile, normalizes each item's label to a POSIX env-var name (`openai-api-key` → `OPENAI_API_KEY`), and spawns a subprocess with all of them injected. Subprocess stdout/stderr text is **never forwarded to the model**, same §RED1 contract as the single-item tool.

<Warning>
  **Profile is the trust boundary.** Items in other profiles are NEVER injected, even when the
  agent has `mount_env` grants on them. A `profileId` belonging to another organization returns
  `PROFILE_NOT_FOUND` (existence is not leaked).
</Warning>

<Warning>
  Subprocess output text is not returned. The model receives only the exit code, duration,
  output-line count, truncation flag, and the count of injected env vars. Same redaction model
  as `run_with_secret`.
</Warning>

## Input

| Field | Type | Required | Description |
|---|---|---|---|
| `profileId` | string | yes | Profile to bulk-mount from. Trust boundary. |
| `command` | string | yes | Command to run |
| `args` | string[] | no | Command arguments |
| `purpose` | string | no | Caller-declared purpose. Recorded per-item in audit. |

## Output

```json
{
  "exitCode": 0,
  "durationMs": 73,
  "outputLineCount": { "stdout": 5, "stderr": 0 },
  "truncated": false,
  "injectedCount": 7
}
```

| Field | Description |
|---|---|
| `exitCode` | Subprocess exit code |
| `durationMs` | Wall-clock milliseconds from handler entry to subprocess completion |
| `outputLineCount` | Number of lines captured per stream (diagnostic only — text is not returned) |
| `truncated` | `true` if either stream hit the 8 KB per-stream capture cap |
| `injectedCount` | How many env vars were actually injected after the structural filter and bulk-skip rules. Lets the model tell "no items in profile" from "subprocess just had nothing to do." |

## Eligibility

Only items with **exactly one string field** participate. `abadge import .env` produces this shape; multi-field items (login, certificate, ssh_key) are silently skipped — use [`run_with_secret`](/mcp/tools/run_with_secret) with `field` for those.

## Hard rules (refuses to silently misbehave)

| Condition | Result |
|---|---|
| Label normalizes to a reserved env var (`PATH`, `LD_PRELOAD`, `NODE_OPTIONS`, `HTTPS_PROXY`, `BASH_ENV`, …) | Whole call errors with the offending item id |
| Two items normalize to the same env var | Whole call errors with both ids |
| A single item's secret exceeds 4 KB | Whole call errors with the offending env-var name (use `mount_secret` for that one item) |
| More than 256 items match server-side | `BAD_REQUEST` with `meta.limit = 256` |

## Capture bounds

- Each stream is bounded to **8 KB** (`STREAM_CAP_BYTES`) to prevent OOM from a misbehaving subprocess.
- `truncated: true` is set when either cap dropped data.

## What the model sees

- Exit code, duration, output-line counts, truncation flag, injected count.

## What the model does not see

- Stdout or stderr text in any form (plain, redacted, encoded, or truncated)
- Raw secret bytes
- Item labels or env-var names that didn't make it into the spawn (e.g. items skipped by the structural filter)
- The host's real environment variables

## Permission required

`mount_env` on every item that should participate, granted to the MCP agent. Local agents only — remote MCP agents are rejected at the gate.

## Errors

| Code | Cause |
|---|---|
| (runtime throw) | A single secret exceeds 4 KB; or a label normalizes to a reserved env var; or two items collide on the same name |
| `PERMISSION_DENIED` | Remote MCP agent attempted bulk mount |
| `PROFILE_NOT_FOUND` | `profileId` belongs to another org or doesn't exist |
| `BAD_REQUEST` | More than 256 matching items in the profile (with `meta.limit = 256`) |

Errors are returned as `{ error, code, hint, meta }` JSON content. See [error responses](/mcp/security#error-responses).

## Audit

One `access.mount_env` row per included item, tagged `meta.viaBulk = true`, with `profileId` populated. Bulk does NOT collapse audit history. Auditors should treat bulk audit rows as "the agent received the data" — the daemon-side structural skip for multi-field items happens after the audit row is written, so the audit count may be ≥ the count actually injected into the subprocess.

## Example

```json
{
  "name": "run_with_all_secrets",
  "arguments": {
    "profileId": "prof_dev",
    "command": "node",
    "args": ["server.js"],
    "purpose": "start dev server with all configured secrets"
  }
}
```

The MCP server:

1. Calls `access.bulkMountEnv({ profileId: "prof_dev" })` — server returns every `mount_env`-granted item in that profile.
2. For each ZK item, decrypts in-process via the daemon (XChaCha20-Poly1305 with AAD bound to profileId+itemId+contentVersion).
3. Applies the structural filter; normalizes each label to a POSIX env-var name.
4. Hard-rejects on collisions / reserved names / oversize secrets.
5. Spawns `node server.js` with the merged env.
6. Returns `{ exitCode, durationMs, outputLineCount, truncated, injectedCount }`.
