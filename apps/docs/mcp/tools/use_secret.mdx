---
title: "use_secret"
description: "Run a command with one secret, or with every env-shaped secret in a profile, injected as env vars. Returns exit code, duration, line counts, and a truncation flag. Subprocess output is never returned to the model."
---

`use_secret` is the unified runtime tool. It replaces the older
`run_with_secret` (single-item) and `run_with_all_secrets` (bulk profile)
tools — pick a mode by providing exactly one target field.

<Warning>
  Subprocess stdout/stderr text is **never forwarded to the model**. The
  model receives only the exit code, duration, output-line count, and a
  truncation flag. If the model needs to read subprocess output, route it
  through a separate audited channel (write to a file via
  [`mount_secret`](/mcp/tools/mount_secret), then read it explicitly).
  This prevents the full set of semantic-leakage vectors (base64, hex,
  URL-encoded, nth-char, byte-split) that string-based redaction cannot
  catch.
</Warning>

## Targets

Provide exactly one. They are mutually exclusive:

| Field | Mode | Selects |
|-------|------|---------|
| `itemId` | single-item | one item by id |
| `profileLabel` | bulk | every env-shaped item in the profile, by profile id |
| `profileExternalId` | bulk | every env-shaped item in the profile, by `externalId` |

## Input

| Field | Type | Required | Description |
|------|------|----------|-------------|
| `command` | string | yes | Command to run |
| `args` | string[] | no | Command arguments |
| `purpose` | string | no | Caller-declared purpose. Audited. |
| `field` | string | no | Named field (single-item mode only) |
| `envVarName` | string | no | Env var name for single-item mode. Default `ABADGE_SECRET`. |

## Output

```json
{
  "exitCode": 0,
  "durationMs": 73,
  "outputLineCount": { "stdout": 5, "stderr": 0 },
  "truncated": false,
  "injectedCount": 7
}
```

`injectedCount` appears only in bulk mode.

## Bulk-mode rules

* Only single-string-field items participate; multi-field items
  (logins, certs, ssh_keys) are silently skipped.
* Labels are normalized to POSIX env-var names
  (`openai-api-key` → `OPENAI_API_KEY`).
* Two items normalizing to the same env var name fail the call with both
  offending IDs.
* A label normalizing to a reserved env key (`LD_PRELOAD`, `NODE_OPTIONS`,
  `PATH`, …) fails the call with the offending item ID.
* Per-secret 4 KB size cap; oversize secrets are refused before spawn —
  use [`mount_secret`](/mcp/tools/mount_secret) instead.
* Cap of 256 items per call.
* Each included item produces one `access.use` audit row tagged
  `meta.viaBulk = true`.
* `use` is local-only — remote agents cannot use bulk mode.

## Errors

Returned as JSON text content:

```json
{
  "error": "Provide exactly one of itemId, profileLabel, or profileExternalId.",
  "code": "BAD_REQUEST",
  "hint": "These fields are mutually exclusive.",
  "meta": null
}
```
