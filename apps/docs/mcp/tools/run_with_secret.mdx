---
title: "run_with_secret"
description: "Run a command with a secret injected as an env var. Returns redacted, capped output. The secret never reaches the model."
---

`run_with_secret` is the workhorse MCP tool. It calls `access.mount` with `mountType: env`, spawns a subprocess with the secret in its environment, captures stdout/stderr, redacts the secret from the output, and returns the result to the model.

The model never sees the secret value or the subprocess's full output.

## Input

| Field | Type | Required | Description |
|---|---|---|---|
| `itemId` | string | yes | ID of the item to inject |
| `field` | string | no | Named field for multi-field items |
| `command` | string | yes | Command to run |
| `args` | string[] | no | Command arguments |
| `envVarName` | string | no | Environment variable name. Defaults to `ABADGE_SECRET`. |
| `purpose` | string | no | Caller-declared purpose. Recorded in audit. |

## Output

```json
{
  "exitCode": 0,
  "stdoutLines": ["line 1", "line 2"],
  "stderrLines": [],
  "truncated": false
}
```

| Field | Description |
|---|---|
| `exitCode` | Subprocess exit code |
| `stdoutLines` | Captured stdout lines, **with the secret replaced by `[REDACTED]`** |
| `stderrLines` | Same for stderr |
| `truncated` | `true` if either stream hit its pre-redaction cap, or if the combined post-redaction output hit the 4 KB budget |

## Caps and redaction

- Each stream is bounded to **8 KB pre-redaction** (`MAX_OUTPUT_BYTES * 2`) to prevent OOM from a misbehaving subprocess.
- Combined post-redaction output is capped at **4 KB**. stdout gets priority; stderr gets the remaining budget.
- `truncated: true` is set when either cap dropped data.

Redaction uses **exact substring replacement**: the server scans stdout and stderr for the literal bytes of the secret and replaces each occurrence with `[REDACTED]`.

<Warning>
  Redaction is best-effort defense in depth, not a guarantee. It does not catch transformed forms — base64-encoded, URL-encoded, JSON-escaped, or split-across-chunks copies of the secret will leak. If a tool must emit data derived from the secret, the subprocess is responsible for scrubbing it.
</Warning>

See [Security model](/mcp/security) for the full discussion.

## What the model sees

- The exit code
- Up to 4 KB of redacted output
- The truncation flag

## What the model does not see

- Raw secret bytes
- Untruncated output
- Subprocess environment dump
- Filesystem paths
- The host's real environment variables

## Permission required

`mount_env` on the item, granted to the MCP agent. Local agents only.

## Errors

| Code | Cause |
|---|---|
| `PERMISSION_DENIED` | No matching `mount_env` permission |
| `MULTI_FIELD_ITEM` | Item has multiple fields and `field` was omitted |
| `FIELD_NOT_FOUND` | Specified field doesn't exist |
| `INVALID_CAPABILITY_LOCALITY` | The MCP agent isn't local |
| `ITEM_NOT_FOUND` | Item ID unknown or deleted |

Errors are returned as `{ error, code, hint, meta }` JSON content. See [error responses](/mcp/security#error-responses).

## Audit

`access.mount_env` — one row per call, with `surface: "mcp"`, the agent ID, the item ID, the field (if any), and the declared purpose.

## Example

The model emits:

```json
{
  "name": "run_with_secret",
  "arguments": {
    "itemId": "item_01HZ...",
    "field": "token",
    "command": "curl",
    "args": ["-fsSL", "-H", "Authorization: Bearer $ABADGE_SECRET", "https://api.example.com/me"],
    "envVarName": "ABADGE_SECRET",
    "purpose": "fetch user profile"
  }
}
```

The MCP server:

1. Resolves `token` from the item.
2. Spawns `curl ...` with `ABADGE_SECRET=<value>` in its env.
3. Captures stdout/stderr, replaces `<value>` with `[REDACTED]`.
4. Returns `{ exitCode, stdoutLines, stderrLines, truncated }`.
