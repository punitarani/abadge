title: "Introduction"
description: "abadge is the credential control plane for AI agents. Store secrets, scope agent access, control delivery, audit everything."
---

abadge gives teams a single place to store credentials, decide which AI agents can use them, and see exactly what happened. Instead of scattering API keys across environment variables or giving agents broad access to a vault, abadge puts a policy-checked, audited gateway between every agent and every credential.

## How it works

```
Store → Permission → Deliver → Audit
```

<Steps>
  <Step title="Store">
    Credentials live in abadge encrypted at rest. Pick **zero-knowledge** mode (the server never sees plaintext) or **server-managed** mode (server-side AES-256-GCM, accessible to remote agents).
  </Step>
  <Step title="Permission">
    Every agent must be explicitly granted access to each credential, scoped to a specific capability and optional expiry. No wildcards.
  </Step>
  <Step title="Deliver">
    Pick the delivery mode: env-var injection, file mount with `0600` permissions, or direct reveal over HTTPS. MCP tools never expose raw secrets to the LLM.
  </Step>
  <Step title="Audit">
    Every access attempt — allowed or denied — is appended to an immutable audit log with the agent, item, capability, delivery mode, and outcome.
  </Step>
</Steps>
