This walkthrough takes you from zero to a running `abadge run` in about five minutes.

## Prerequisites

- macOS or Linux (x86_64 or arm64)
- An [abadge.io](https://abadge.io) account, or a self-hosted API URL

## 1. Install the CLI

<CodeGroup>
```bash macOS / Linux
curl -fsSL https://raw.githubusercontent.com/punitarani/abadge/main/install.sh | bash
```

```bash Verify
abadge --version
```
</CodeGroup>

The installer detects your OS and libc, downloads the latest signed CLI release, verifies the SHA-256 checksum, installs to `~/.abadge/bin/abadge`, and adds it to your shell profile.

## 2. Authenticate

```bash
abadge login
```

The CLI starts a device-code flow and opens your browser. Approve the request to attach your CLI to your account. The bearer token is held in **daemon memory only** — never written to disk.

<Tip>
  `abadge login` does not register any agents. The next step registers the local runtime agent that `abadge run` uses.
</Tip>

## 3. Set up an organization and profile

If you don't have an org yet, create one:

```bash
abadge org create --name "Acme"
abadge org use acme
```

Then create (or switch to) a profile:

```bash
abadge profile create --name default --storage-mode server_managed
abadge profile use default
```

Server-managed is the simplest storage mode. For zero-knowledge profiles, bootstrap them in the [dashboard](https://abadge.io) before adding items.

## 4. Register the CLI's runtime agent

`abadge run` needs a `local_cli` agent to authenticate with. The CLI generates an Ed25519 keypair, uploads the public key, and writes the private key to `~/.abadge/agents/` with `0600` permissions:

```bash
abadge agent register --kind local_cli --name "dev-laptop"
```

The command updates `~/.abadge/config.json`'s `localAgents.cli` automatically. Re-run it any time you want to rotate the keypair.

## 5. Store a secret

```bash
abadge item create \
  --label "OpenAI API key" \
  --kind api_key \
  --storage-mode server_managed
```

The CLI prompts for the value interactively (echo-masked). Server-managed items are encrypted with AES-256-GCM by the API.

Note the item ID from the success message. You'll need it in the next step.

## 6. Grant the CLI agent access

Permissions are explicit: agent + item + capability.

```bash
abadge permission create \
  --agent-id <cli-agent-id> \
  --item-id <item-id> \
  --capability mount_env
```

Find the `cli-agent-id` with `abadge agent list` (it's the agent with kind `local_cli`).

## 7. Use the secret

Inject the secret as an environment variable into any command:

```bash
abadge run \
  --item <item-id> \
  --env-var OPENAI_API_KEY \
  -- node script.js
```

Under the hood, the CLI:

1. Mints a short-lived `abs_...` session for the `local_cli` agent.
2. Calls `access.mount` with `mountType: env`.
3. Spawns `node` with `OPENAI_API_KEY=<value>` in its environment.

The secret lives only in the child's process memory. It never touches disk and never appears in shell history.

## What just happened

<Steps>
  <Step title="Stored">
    The secret was encrypted with AES-256-GCM and persisted as ciphertext.
  </Step>
  <Step title="Permissioned">
    A capability grant was recorded against `(agent, item, capability)`. No wildcards, no implicit access.
  </Step>
  <Step title="Delivered">
    The secret was injected into a subprocess env var. It never appeared in your shell history.
  </Step>
  <Step title="Audited">
    Every step — login, agent register, item create, permission create, mount — was appended to the immutable audit log. View it with `abadge audit`.
  </Step>
</Steps>

## Remote agent variant

If you want a remote agent (CI runner, cloud worker) to consume the secret over HTTPS instead:

```bash
# Register a remote agent with a one-time bootstrap token
abadge agent register --kind remote --name "ci-bot"
# → prints agent ID + abe_... bootstrap token (save it)

# Grant reveal_plaintext instead of mount_env
abadge permission create \
  --agent-id <remote-agent-id> \
  --item-id <item-id> \
  --capability reveal_plaintext
```

The remote agent enrolls with the bootstrap token (via the SDK or API), then calls `access.reveal` for the plaintext. See [AbadgeAgentClient](/api/sdk/agent-client) for the SDK side.
